# Гейты качества: Deno

Сверено 26.08.2026. Источники, версии и способ перепроверки —
`docs/research/2026-08-26-quality-gates.md`.

Особенность стека: четыре роли из шести закрыты самим рантаймом, без
зависимостей. Две закрыты плохо — и это надо знать заранее, а не выяснять на
приёмке.

## Обязательный набор

| Роль | Команда | Примечание |
|---|---|---|
| Формат | `deno fmt --check` | встроено |
| Линт | `deno lint` | встроено; наборы правил и исключения — в `deno.json` |
| Типы | `deno check` | встроено; проверяет и удалённые модули |
| Тесты и порог | `deno test --coverage=cov` затем `deno coverage cov --threshold=N` | `--threshold` применяется к строкам, ветвям и функциям сразу |
| Мёртвый код | пробел, см. ниже | |
| Границы | пробел, см. ниже | |

## Два пробела и что с ними делать

**Мёртвый код.** Готового аналога нет. Что работает: `deno info <точка входа>`
строит граф модулей — файл проекта, которого в графе нет, не используется.
Проверка сводится к сравнению графа со списком файлов и делается скриптом на
десяток строк, а не инструментом. Если проект живёт в npm-совместимом режиме
(`node_modules`, `package.json`), подходит `knip`.

**Границы модулей.** Установившегося инструмента нет: анализаторы графа
рассчитаны на относительные и пакетные импорты, а не на URL. Что работает:
держать межблочные импорты только через точку входа блока (`mod.ts`) и
проверять запретом на глубокие пути тем же скриптом над `deno info`. Правило
формулируется из графа блоков техплана так же, как в остальных стеках, —
меняется только способ проверки.

Пробел закрывать самописным скриптом в проекте, а не тянуть инструмент из
другого рантайма: `dependency-cruiser` разберёт локальные файлы и молча
пропустит все URL-импорты, то есть даст ложное «нарушений нет».

## Ловушки

- `deno coverage` без `--threshold` печатает отчёт и завершается успешно: порог
  не подразумевается, его надо задать.
- `deno check` без аргументов проверяет не всё: указывать точки входа явно.
- Правила `deno lint` включаются наборами (`tags`) и по одному; список
  доступных — `deno lint --rules`. Проверять его при обновлении рантайма:
  правила добавляют между версиями.

## Ситуативные

| Проверка | Чем | Условие |
|---|---|---|
| Диф контракта API | `oasdiff` на сгенерированной схеме | фронт и бэк раскатываются раздельно |
| Бюджеты | Lighthouse CI | есть живой трафик и веб-интерфейс |
| Доступность | axe в браузерном прогоне | появились экраны |

Мутационного прогона зрелого уровня для этого рантайма нет. Если критичный
модуль есть, а инструмента нет — остаётся правило из принципов проекта:
проверка, которая не падает на испорченном входе, — не проверка; порчу вносить
вручную и подтверждать, что она применилась.
