# Гейты качества: Python

Сверено 26.08.2026. Источники, версии и способ перепроверки —
`docs/research/2026-08-26-quality-gates.md`.

## Обязательный набор

| Роль | Команда | Чем |
|---|---|---|
| Формат | `ruff format --check .` | Ruff, он же линтер — один инструмент вместо трёх |
| Линт | `ruff check .` | наборы правил включаются явно в `pyproject.toml` |
| Типы | `mypy --strict .` | на новом проекте `--strict` сразу; на готовой базе он неподъёмен |
| Тесты и порог | `pytest --cov --cov-fail-under=N` | `pytest-cov`; порог по факту, округлённому вниз |
| Мёртвый код | `vulture .` и `deptry .` | `vulture` — код, `deptry` — неиспользуемые и незаявленные зависимости |
| Границы | `lint-imports` | `import-linter`, контракты в `.importlinter` или `pyproject.toml` |

## Ловушки границ

- `root_packages` — **список**, и одну строку `root_packages = myproject` парсер
  разбирает посимвольно: падает с `Could not find package 'm' in your Python
  path` ещё до проверки контрактов. Значение писать с новой строки с отступом
  (как ниже) либо использовать `root_package` в единственном числе. Ловушка
  тихая по последствиям: проект остаётся вообще без роли «границы модулей», а
  выглядит так, будто контракты есть.
- Импорт под `if TYPE_CHECKING:` — тоже нарушение (проверено: `exit=1` с
  указанием звена и строки). Поведение верное — зависимость по типам означает,
  что нижний слой знает форму верхнего, — но неочевидное. Выход не исключение в
  конфиге, а `Protocol` в нижнем слое.
- Обход через промежуточный модуль внутри слоя не помогает: цепочка
  `core.mod -> core.utils -> api` ловится и печатается целиком.

## Границы из графа блоков

`import-linter` описывает контракты словами, поэтому граф блоков переносится в
него почти дословно:

```ini
[importlinter]
root_packages =
    myproject

[importlinter:contract:layers]
name = Блоки идут слоями, обратный импорт запрещён
type = layers
layers =
    myproject.web
    myproject.api
    myproject.core

[importlinter:contract:core-independent]
name = Ядро не знает про доставку
type = forbidden
source_modules = myproject.core
forbidden_modules =
    myproject.web
    myproject.api
```

`layers` — прямая запись графа: верхний слой знает про нижний, нижний про
верхний — нет. `forbidden` — для пар, которых в графе нет вообще.

## Наборы правил Ruff, которые стоит включить явно

| Набор | Что ловит |
|---|---|
| `E`, `F` | базовые ошибки и неиспользуемое |
| `I` | порядок импортов |
| `B` | ловушки bugbear: мутабельные значения по умолчанию, `except` без типа |
| `S` | правила безопасности (перенесены из Bandit — отдельный инструмент не нужен) |
| `ASYNC` | блокирующие вызовы внутри `async` |
| `RUF` | правила самого Ruff, в том числе неиспользуемый `noqa` |

## Ловушки

- `mypy --strict` на существующем коде даёт сотни ошибок. Либо включать до
  первой строки, либо по модулям через `[[tool.mypy.overrides]]` — но тогда
  список исключений обязан сокращаться, а не расти.
- `vulture` ложно срабатывает на динамике (обработчики, плагины, точки входа
  фреймворка). Ему нужен файл исключений, и каждая строка в нём — с причиной.
- `--cov-fail-under` без `--cov` молча ничего не проверяет: флаги идут парой.
- Правила безопасности `S` шумят в тестах (`assert`, временные файлы) —
  исключать по каталогу тестов, а не глобально.

## Ситуативные

| Проверка | Чем | Условие |
|---|---|---|
| Мутационный прогон | `mutmut`, ограниченный критичным модулем | есть модуль, где ошибка стоит денег |
| Диф контракта API | `oasdiff` на сгенерированной схеме | фронт и бэк раскатываются раздельно |
| Карантин пакетов | закреплённый лок-файл, запрет исполнения кода при установке | продукт в бою |

## Отклонено

- Отдельный Bandit — его правила есть в Ruff как набор `S`.
- Отдельный isort и Black — покрыты Ruff.
- Порог дублирования — та же причина, что в остальных стеках.
