# Ресерч: проверки качества кода, которые стоит выдавать проекту

> Дата сверки — 26.08.2026. Основание для скилла `skills/forge-quality-gates/`.
> Перепроверить 26.11.2026 или раньше по событию (см. «Как перепроверять»).

## Зачем

Качество кода построенного продукта держалось на трёх словесных обещаниях:
принципы проекта, «проверяй фактически» в определении блок-агента и «тесты —
часть задачи» у исполнителя. Ни одной машинной проверки в приёмке блока не
было. Правило без исполнителя работает вероятностно, и хуже всего это заметно
у агента: он читает правило ровно в том ходу, когда до него дошло внимание.

## Метод

Версии и даты релизов сверены с реестрами пакетов 26.08.2026 (npm, PyPI),
поддержка текущего мажора линтера — по полю `peerDependencies`, а не по
README. Практики — по первоисточникам (документация инструментов, спецификации,
исследования), не по обзорным статьям.

## Находки, из-за которых каталог и нужен

1. **Популярность не равна пригодности.** `eslint-plugin-jsx-a11y` — 45 млн
   загрузок в неделю и обязательный пункт любой подборки по доступности.
   Последний релиз — октябрь 2024, поддержки текущего мажора ESLint нет,
   заявка открыта. Каталог без даты сверки уверенно посоветовал бы мёртвый
   инструмент.
2. **README отстаёт от манифеста.** У `eslint-plugin-sonarjs` в README указаны
   ESLint 8 и 9, в `package.json` peer включает 10. Сверять поле, не текст.
3. **Пресеты плагинов пересекаются.** `sonarjs` в режиме «рекомендованное»
   включает почти все свои правила уровнем «ошибка» и пересекается с
   `typescript-eslint`; `unicorn/no-negated-condition` дублирует
   `sonarjs/no-inverted-boolean-check`. Берутся конкретные правила.
4. **Часть правил уже включена и не нуждается в прозе.** Пресет
   `strictTypeChecked` содержит `no-unnecessary-condition`,
   `no-unnecessary-boolean-literal-compare`, `no-misused-spread`,
   `no-deprecated`. Проверено по исходнику пресета, не по документации.
5. **Мажоры идут быстро.** TypeScript 6.0 вышел в марте 2026, 7.0 — в июле
   2026 (компилятор переписан на Go). ESLint 9 снят с поддержки, актуален 10.
   Отсюда срок перепроверки в три месяца, а не в год.
6. **У кода, написанного моделью, дубли растут, а доля рефакторинга падает** —
   на выборке 623 млн изменений 2023–2026. Это довод за проверку мёртвого кода
   и за границы модулей, но не за порог дублирования: порог противоречит
   правилу «абстракция после устоявшегося повтора» и падает там, где повтор
   уместен.

## Как перепроверять

Срок — 26.11.2026. Раньше срока перепроверять по событию: мажорная версия
линтера, компилятора или рантайма; падение линта сразу после обновления
зависимостей; инструмент перестал релизиться.

Порядок на каждый инструмент из таблицы:

```bash
# npm: версия, дата релиза и поддержка мажора линтера
curl -s "https://registry.npmjs.org/<пакет>" | python3 -c "
import sys,json;d=json.load(sys.stdin);v=d['dist-tags']['latest']
print(v, d['time'][v][:10], (d['versions'][v].get('peerDependencies') or {}).get('eslint','-'))"

# PyPI: версия и дата релиза
curl -s "https://pypi.org/pypi/<пакет>/json" | python3 -c "
import sys,json;d=json.load(sys.stdin);i=d['info']
print(i['version'], d['releases'][i['version']][0]['upload_time'][:10])"
```

Признаки, по которым инструмент выводится из каталога: релиза нет больше года
**и** открыта заявка на поддержку текущего мажора линтера или рантайма; либо
его роль перешла к встроенному средству (как правила Bandit к Ruff).

Состав правил пресета проверяется по исходнику пресета, а не по его описанию.
